# Sonic Radar 声音方向分析及 EchoRadar v3 应用

> 需求来源：用户于 2026-09-12 提供的完整分析正文。下文保留需求及其引用；引用不是本机实测结果。ASUS 已公开功能、公开算法参考、EchoRadar 自主实现与未经验证的假设应分别解读。

## 一、资料能够证明什么

需要区分三类内容：

| 类型 | 能够确认的内容 |
| --- | --- |
| ASUS 官方产品资料 | 雷达、方向箭头、频段筛选、灵敏度、信号持续时间等功能 |
| 公开多声道方向算法 | 如何从声道频谱与声道空间布局生成方向活动图 |
| EchoRadar 自主设计 | CS2 适配、事件分类、低延迟采集、多源处理和双耳方向估计 |

**公开算法不能直接称为 Sonic Radar 的完整内部实现。** 仓库引用的 US9232337B2 来自 A-VOLUTE，本文将其作为技术参考，不据此断言 ASUS 各代产品使用完全相同的算法、参数或驱动链路。[公开专利](https://patents.google.com/patent/US9232337B2/en)

## 二、多声道方向分析原理

多声道音频中，每个声道对应一个已知的扬声器方向。公开参考方法先对每个声道进行短时频谱分析，再对每个频率分量计算方向能量：

```text
声道能量：Pₖ(f) = |Xₖ(f)|²
方向向量：V(f) = Σ Pₖ(f) · uₖ
```

其中 `uₖ` 是该声道方向的单位向量。合成向量的朝向表示该频率附近的主要方向；随后进行频率加权，并把贡献累计到雷达扇区。[算法说明](https://patents.google.com/patent/US9232337B2/en)

它估计的是**混音所表达的声音方向活动**，不能直接得到游戏对象坐标。

举例来说，右前与右后声道共同承载一个声音时，合成结果可能落在右侧；方向显示不必局限于实际扬声器的位置。

但多个同频声音可能互相影响：等强的相反方向成分会使合成向量抵消。因此，一个方向峰不一定对应一个独立人物，没有方向峰也不一定代表没有声音。这是上述向量计算的直接限制。

## 三、脚步／枪声频段筛选的作用

ASUS 公开资料介绍了按声音频段选择雷达信号，以及调整灵敏度、显示保持时间；官方手册还展示了脚步、枪声等频段类别。[ASUS 手册](https://dlcdnet.asus.com/pub/ASUS/mb/SocketAM4/CROSSHAIR-VI-HERO/E12653_ROG_ROG_STRIX_Z200_Series_SW_EM_WEB_20170419.pdf)

频段筛选的作用是：**让目标声音常出现的频率对雷达贡献更多。**

它不能单独证明声音类别。脚步、枪声、换弹、语音和环境声可能共享频段；不同材质、距离和遮挡也会改变同一种声音的频谱。

v3 应当先比较：

1. 纯频段筛选。
2. 频段筛选加瞬态、持续时间及节奏判断。
3. 当前冻结参数的事件模型。

使用同一套真实 CS2 测试录音，分别统计误报、漏报、方向误差和延迟。没有对比结果前，不宣称 Sonic Radar 类方法分类更准确。

## 四、为什么耳机能听出方向

耳机通常只有左右两个输出。方向感可以来自双耳到达时间差、音量差及方向相关的频谱变化。

Valve 的 Steam Audio 文档明确说明，HRTF 双耳渲染使用两个输出声道。因此：

> 人耳能分辨前后，不等于 app 能拿到独立的前后声道。

[Valve 双耳渲染文档](https://valvesoftware.github.io/steam-audio/doc/unreal/spatialization-settings.html)

多声道能量算法与双耳方向估计解决的是不同输入问题，不能直接互换。

## 五、对 CS2 的适用性与 fallback

Audio Radar 厂商的当前说明将 CS2 列为仅有 3D 立体声、缺少独立环绕输出。需要通过本机实际录制复核，而不是套用 CS:GO 的设置教程。[CS2 兼容说明](https://support.audioradar.com/portal/en/kb/articles/counter-strike)

v3 首先检查：

- 端点格式与声道角色是否正确。
- 逐声道测试能否保留独立通道。
- CS2 的受控方向场景是否产生有效的独立空间信息。
- 驱动是否仅复制、升混或重新渲染双声道内容。

**仅看到“8 声道”，甚至所有声道都有波形，都不足以证明 CS2 输出了原始 7.1。**

若真实多声道成立，采用多声道方向引擎；若只有双耳音频，则：

- 游戏直接播放到耳机，app 旁路采集。
- 先尝试分频段双耳特征与 CS2 实录方向模板。
- 前后判别不足时，训练独立的 CS2 双耳方向模型。
- 不确定时返回方向范围或拒判，并同时统计输出覆盖率。
- 频段事件检测未达标时，再启用后续事件检测器方案。

双耳 fallback 是待验证的工程路线，不能保证任意复杂混音都能准确恢复方向。

## 六、v3 应当保留的设计原则

- 方向分析与事件分类分开评测，再验证两者关联是否正确。
- 频段响应不能直接当作脚步／枪声分类置信度。
- 耳机播放不能等待分析或模型推理。
- 雷达动画流畅不代表方向正确。
- 验收必须包含同时发生的脚步与枪声、遮挡、混响及玩家转身。
- 保留公开算法来源说明，明确哪些参数和改进属于 EchoRadar 自主设计。
