# EchoRadar v3：面向 CS2 的实时声音方向工具

> 需求来源：用户于 2026-09-12 提供的完整 v3 计划，整理 Markdown 排版，不缩减验收要求。本文是目标，不是完成报告。实施状态见 [P0](v3-p0-status.md)，技术来源边界见 [Sonic Radar 分析](sonic-radar-analysis.md)。

## 1. 目标与技术结论

**v3 全面重写，保留现有 event recognition 模型及其默认参数。核心验收目标是：使用耳机玩 CS2 时，实时显示脚步、枪声的方向，同时优先保证听音延迟。**

已经查证：

- **听得出方向，不代表输入是 5.1/7.1。** HRTF 可以把空间线索编码到两个声道；Valve 文档明确说明双耳渲染使用立体声输出。[Steam Audio 文档](https://valvesoftware.github.io/steam-audio/doc/unreal/spatialization-settings.html)
- Audio Radar 厂商目前将 CS2 标为仅提供 3D 立体声、缺少独立环绕输出。它不能代替本机实测，但足以说明不能直接承诺“开启 Windows 7.1 即可定位”。[CS2 兼容说明](https://support.audioradar.com/portal/en/kb/articles/counter-strike)
- Sonic Radar 的公开资料支持学习其**频段筛选、方向能量显示、灵敏度、信号保持和主要声音箭头**；目前没有证据证明其脚步／枪声分类准确率优于现有模型，也没有完整公开实现可直接移植。[ASUS 说明](https://www.asus.com/MICROSITE/mb/ROG-supremefx-gaming-audio/us/sonic_radar.html)

因此，v3 配备两种输入路线：

| 实际输入 | 方向方案 | 耳机播放 |
| --- | --- | --- |
| 独立 5.1/7.1 | 多声道方向分析 | 原设备播放，或一次双耳渲染后转发 |
| CS2 双耳立体声 | CS2 专用双耳方向估计 | 游戏直接播放，app 旁路分析 |

双耳方案具备原型研究价值，但复杂场景准确率尚未验证。**未通过 CS2 实测前，不将 v3 标为已完成核心目标。**

## 2. 重构内容与算法路线

### 项目与基础架构

- 开始实施时保存当前 v2 状态，包括未提交修改；建立 `codex/v3`，旧版本通过版本历史保留。
- 重写采集、方向分析、运行时、设置、日志、UI、HUD 和测试；删除旧方向模型兼容层及旧产品路径。
- 保留当前默认 `v4-candidate` 模型包、特征契约和原始参数，以及复现识别所必需的测试资料。旧实验资产归档，不继续接入产品。
- 使用 C++20、CMake、WASAPI、ONNX Runtime；分析内部统一 48 kHz，保存输入声道角色及时间戳。
- 采集、分析、推理和 UI 分线程运行；音频回调只搬运数据，播放不等待识别结果。
- 默认沿用本地运行的项目定位：运行时只分析音频，不读取游戏坐标、不注入游戏；首发输出玩家视角的水平相对方向，不宣称敌我身份、距离或高度。

### 事件检测：先尝试 Sonic Radar 类方法

1. 实现可复现的频段筛选基线：短时频谱、分频段能量、自适应噪声底、瞬态起音、持续时间和重复节奏。
2. 分别建立脚步、枪声候选规则；频段与阈值使用 CS2 开发录音校准，不把某一频段直接等同于某个类别。
3. 同时评测“纯频段筛选”和“频段＋时间特征”，确认改善来自哪里。
4. 现有模型作为可选辅助和对照，默认参数不变；调整入口放在“设置 → 高级 → 实验室 → 旧识别模型”。
5. 若传统方法达不到验收门槛，再新增 CS2 事件检测器；与旧模型分包管理，不悄悄修改旧权重或默认参数。

### 方向估计与事件关联

- **多声道路线：**按真实声道角色分析短时频谱、能量及方向一致性；LFE 不参与定位。保留多个候选方向，避免只用全局平均把相反方向声音抵消。
- **双耳路线：**先使用分频段左右电平差、互相关时差、相干性，以及真实 CS2 定向录音建立的模板估计方向。前后判别不能只靠左右音量差。
- 若模板方案达不到方向门槛，训练独立、因果运行的 CS2 双耳方向模型；使用实录验证，不能把通用 HRTF 合成数据当作最终效果证明。
- 在同一事件时间窗内关联类别与方向。遇到脚步、枪声重叠，不把全部方向峰都标成同一种事件；无法可靠关联时显示未分类声音或方向不确定。
- HUD 使用短时标记，默认约 250 ms 衰减；不将旧方向当作随玩家转身更新的世界坐标。

### 新接口

新增统一的：

- `AudioFrame`：PCM、采样率、声道角色、时间戳、流代次。
- `DetectionResult`：事件类别、起音时间、方向候选、分类／方向置信度、所用算法及拒判原因。
- `RuntimeSnapshot`：设备、音频链路、检测结果、延迟与错误状态；UI 通过命令接口修改设置。

设备切换、断流或格式改变时，统一清空时序状态与过期 HUD 标记。v3 使用独立设置目录，不自动继承旧 UI 和方向参数。

## 3. 耳机与 5.1/7.1 设置方案

**5.1/7.1 描述的是分析前的音频流；普通 3.5 mm 耳机最终仍接收左右两路声音。**

本机已发现 Senary Audio 和 VB-Audio Virtual Cable，优先验证现有设备。VB-CABLE 官方文档说明其扬声器播放端点支持配置至 7.1，但实际安装版本和格式仍需检查。[VB-CABLE 手册](https://vb-audio.com/Cable/VBCABLE_ReferenceManual.pdf)

### 默认 CS2 路线：优先保持听音链路

1. 耳机连接现有声卡；CS2 输出选择对应的 Senary Audio 耳机／扬声器端点。
2. app 选择同一播放端点进行 WASAPI loopback。
3. 首轮基准测试关闭 Windows 空间音效及额外驱动增强，固定并记录 CS2 音频设置；之后再单独评测用户偏好的处理方式。
4. 游戏直接向耳机播放，app 不重新播放声音；分析缓冲只影响 HUD 出现时间。
5. 向导分别显示“输入格式”“实际空间线索”“方向验证结果”，不因设备名称含 7.1 就判为通过。

### 多声道验证路线

以下转发步骤需要 v3 音频桥完成后使用：

1. `Win + R` 输入 `mmsys.cpl`，进入“播放”。
2. 选择 VB-CABLE 的**扬声器型 CABLE Input**，点击“配置”，选择 5.1 或 7.1。
3. 在“属性 → 高级”设置匹配声道数的 48 kHz 格式；位深使用设备支持的格式。
4. 若通过录音端点采集，在“录制 → CABLE Output → 属性 → 高级”也设置相同声道数和采样率。
5. 将 CS2 输出设备设为该 CABLE Input；其他应用继续输出至物理声卡，减少通知及语音干扰。
6. v3 捕获原始多声道，将它分送方向分析和双耳渲染；双耳渲染结果输出到实际耳机端点。
7. 不启用 Windows“侦听此设备”，不叠加第二套空间渲染；v3 不得将自己的输出重新送回输入。
8. 先运行逐声道测试，再录制 CS2 前后左右定向场景。只有证明存在有效独立方向信息，才启用多声道模式。

**如果 CS2 仍只有双耳内容，恢复直接耳机输出，切换双耳方向方案。** 不使用立体声升混冒充原始环绕。

虚拟转发采用设备支持的低延迟 WASAPI 周期，并处理输入输出时钟漂移。首版不自研驱动；现成驱动的瓶颈经测量确认后，再决定是否值得扩展。驱动无法恢复游戏未输出的原始声道。[微软低延迟音频文档](https://learn.microsoft.com/en-us/windows-hardware/drivers/audio/low-latency-audio)

## 4. 全新 UI 与 HUD

- 使用 **Qt Quick/QML 自定义视觉组件＋C++ 后端**，移除现有 ImGui 产品界面；自定义标题栏、按钮、设备卡和雷达。Qt Quick 支持自定义控件与透明窗口。[Qt 文档](https://doc.qt.io/qt-6/qtquickcontrols-customize.html)
- 采用精简深色游戏工具风格：主页提供开始／停止、设备状态和紧凑雷达；其余入口为“音频设置”“HUD 编辑”“高级诊断”。
- HUD 为独立透明窗口，默认鼠标穿透、不抢焦点；支持拖动、缩放、不透明度、显示器选择和快捷键隐藏。
- 脚步与枪声使用不同形状及颜色；未分类声音使用中性标记，低置信方向显示扇区而非精确箭头。
- 首发以 **CS2 无边框窗口**为 HUD 验收模式；独占全屏支持另行验证，不以游戏注入作为实现前提。
- 音频向导、测试与解释均使用自定义 UI；必须由系统完成的设备配置提供准确跳转和步骤。
- 首页保持简洁，模型阈值、频段参数、原始概率和推理统计集中到高级诊断。

## 5. 实施顺序与验收门槛

以下数值作为开发目标，尚不是已验证性能。

| 阶段 | 交付与完成条件 |
| --- | --- |
| P0：确认可行性 | 本机 CS2 输入格式、独立声道验证、带方向标签的实录；频段事件基线和双耳方向基线报告 |
| P1：v3 音频核心 | 旁路采集、5.1/7.1 支持、离线回放评测、可选低延迟转发、断流恢复 |
| P2：检测与方向 | 先完成传统算法；未达门槛时依次加入专用方向模型、必要的新事件检测器 |
| P3：产品界面 | 自定义 UI、设置向导、透明 HUD、高级诊断及安装包 |
| P4：真实 CS2 验收 | 在实际耳机、声卡和目标机器上测准确率、延迟、稳定性，附原始结果 |

**数据与准确率**

- 测试包含不同地图、地面材质、武器、距离、遮挡、混响、自身声音、语音及同时出现的脚步／枪声。
- 按录制场次和地图拆分开发集与独立测试集，不能用同一段录音调参又验收。
- 脚步、枪声分别以 precision ≥90%、recall ≥80% 为目标；按起音时间 ±100 ms 一对一匹配事件，额外检测计为误报。
- 已正确检出的可定位事件：方向误差中位数 ≤20°、P90 ≤45°、前后混淆率 ≤5%；方向输出覆盖率 ≥80%，防止靠大量拒判取得低误差。
- 另行报告所有真实事件中“类别正确且方向误差 ≤45°”的比例，不能只展示最容易的成功样例。

**延迟与稳定性**

- 默认旁路模式不增加播放缓冲；测量启用前后的实际听音延迟变化。
- 虚拟转发附加听音延迟目标 P95 ≤10 ms；不达标则不作为默认 CS2 链路。
- 音频起音到 HUD 目标 P95 ≤100 ms，测量完整链路而非仅算法耗时。
- 连续运行两小时无持续积压、明显爆音或卡顿；覆盖拔插、默认设备切换、休眠恢复和采样率变化。
- 完成 5.1/7.1 声道映射、静音、LFE、重叠声源及模型兼容测试，并验证多显示器与 100%～200% DPI。

**发布原则：**频段筛选失败就启动后续检测方案；双耳方向方案未达标就继续作为研究版本。真实 CS2 的脚步／枪声方向反馈通过验收，才认定 v3 核心目标完成。
